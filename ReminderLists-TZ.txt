# Техническое задание на Android-приложение «ReminderLists»

Рабочее название приложения: **ReminderLists**

Статус документа: рабочий черновик для дальнейшей разработки промптов/кода LLM.
Три модуля («Списки» — раздел 3, «Напоминалки» — раздел 4, «Notes» — раздел 4A) описаны; схема БД — раздел 6; открытые вопросы — раздел 10.

---

## 1. Общее описание

Приложение для Android, локальное (offline-first), с единой базой данных SQLite.
Состоит из трёх функциональных модулей (три вкладки нижнего бара, см. 3.9):

1. **Списки** — универсальные чек-листы (покупки, дела, что угодно) с элементами, фото, комментариями, справочником часто используемых пунктов, папками, PIN-защитой и т.д. *(раздел 3)*
2. **Напоминалки** — записи, которые срабатывают по времени *(раздел 4)*.
3. **Notes** — долговременные заметки-карточки без срабатывания, с папками и PIN-защитой *(раздел 4A)*.

Все модули работают с общей SQLite-базой в рамках одного приложения.

---

## 2. Термины

| Термин | Значение |
|---|---|
| Список | Именованный набор элементов (чек-лист) |
| Элемент | Строка списка с текстом, статусом «готово», фото |
| Папка | Контейнер для группировки списков (один уровень вложенности) |
| Справочник | Отдельная база часто используемых названий элементов (для автоподстановки и быстрого добавления) |
| Разделитель | Визуальная граница в списке, ниже которой находятся выполненные элементы |

## 3. Функциональные требования

### 3.1 Папки
- Один уровень вложенности (папка → списки; вложенных папок нет).
- Список может быть без папки (лежит в корне).
- Порядок папок — автоматический, по алфавиту (без ручной сортировки).
- Комментарий к папке (свободный текст, необязательный) — по аналогии с комментарием списка. Внутри открытой папки комментарий отображается **внизу**, после перечня списков, под полосой-разделителем (как разделитель «готово» у элементов). Комментарий списка внутри открытого списка — так же: внизу, после элементов, под разделителем.

**Меню действий папки** (иконка «⋮» на папке, и/или долгим нажатием на папку):
- Переименовать
- Редактировать комментарий папки
- Удалить (с подтверждением; при удалении — выбор: удалить все списки внутри или переместить их в корень; если среди списков есть защищённые PIN-ом — перед удалением запрашивается их PIN, см. 3.6)

### 3.2 Список
В перечне списков после названия каждого списка через пробел выводится счётчик **«(готово/всего)»** по элементам списка (тем же размером и цветом, что и название). Пустые списки — без счётчика. Непустые списки в работе — **жирным**; полностью готовые («(7/7)») — обычным начертанием, но зачёркнуты (вместе со счётчиком). У папок после названия — счётчик **«(количество списков)»**, непустые папки — жирным; пустые — без счётчика, обычным.

Атрибуты списка:
- Название
- Папка (опционально)
- Комментарий к списку (свободный текст, необязательный)
- Флаг защиты PIN-ом (см. 3.6)
- Флаг защиты от удаления (см. 3.2a)
- Порядок в папке/корне — автоматический, по алфавиту

Действия:
- Открыть, добавить элементы.
- Включить крупный шрифт / режим презентации (см. 3.5, включается отдельно долгим тапом на FAB, не через меню).

**Меню на списке** (иконка «⋮» на списке в общем перечне списков, и/или долгим нажатием на список):
- Изменить (переименовать / отредактировать)
- В папку (переместить в другую папку / убрать из папки)
- Закрыть PIN-ом / Снять PIN (вкл/выкл PIN, выбор своего PIN или PIN по умолчанию, см. 3.6)
- Запретить удаление / Разрешить удаление (см. 3.2a)
- Удалить (с подтверждением; если список защищён PIN-ом — сначала запрос PIN, см. 3.6)

**Меню внутри списка** (иконка «⋮» в top app bar, когда список уже открыт и видны его элементы):
- Переместить — включает режим выбора элементов для переноса в другой список (см. 3.3)
- Поделиться (см. 3.7)
- Комментарий — редактировать комментарий списка
- Удалить отмеченные — одним действием удаляет все элементы со статусом «готово» (без необходимости входить в режим множественного выбора)
- Снять отметки — одним действием снимает статус «готово» со всех элементов списка сразу

### 3.2a Защита списка от удаления

Отдельный от PIN-защиты (3.6) флаг: список нельзя стереть ни одним из путей удаления. Нужен для списков, которые ведутся годами и не должны пропасть от случайного свайпа.

- **Включение/выключение — пункт меню «⋯» списка**: «Запретить удаление» / «Разрешить удаление».
- **Формулировки пунктов меню не пересекаются словами** (правило раздела 8): PIN-защита названа по своему ключу — «Закрыть PIN-ом» / «Снять PIN», защита от удаления — по своему действию: «Запретить удаление» / «Разрешить удаление». Слово «Защитить» из меню убрано: два пункта, начинавшиеся с «Защитить…», были неразличимы. То же именование PIN-пунктов — в Notes (4A).
- **Ключ — только общий Default PIN** из настроек (5), не собственный PIN списка: иначе защита снималась бы тем же PIN-ом, что и открывается список.
  - Включить защиту можно **только если Default PIN задан**; иначе — снэкбар Warning «Set the Default PIN in Settings first», флаг не меняется (иначе защиту нечем было бы снять).
  - **Снятие защиты требует Default PIN** — иначе её обходили бы в два тапа (снял флаг → удалил).
- **Что блокируется** (всё — с вводом Default PIN, подтверждение и PIN в одном диалоге):
  - удаление самого списка (меню «⋯» и свайп влево);
  - удаление элемента внутри списка (меню «⋯» строки и свайп влево) и пункт «Удалить отмеченные»;
  - удаление вместе с папкой — см. ниже.
- **Не блокируется**: перемещение списка в другую папку/корень, переименование, правка комментария и любая работа с содержимым, кроме удаления.
- **Удаление папки** (3.1), внутри которой есть защищённые списки, — в диалоге удаления папки появляется третий вариант; счётчик N — число защищённых списков в папке:
  1. «Переместить списки в корень» — как обычно, папка удаляется, списки целы;
  2. «Удалить содержимое, N защищённых списков перенести в корень» — обычные списки удаляются, защищённые выживают и уезжают в корень;
  3. «Удалить содержимое вместе с N защищёнными списками» — требует Default PIN.
- Индикатор защиты в строке списка не рисуется — иконка «замок» уже занята PIN-защитой (3.6).

### 3.3 Элемент списка

**Комментарий — только на уровне списка (см. 3.2), у отдельного элемента поля комментария нет.**

Атрибуты элемента:
- Текст (Name)
- Количество (Quantity) — необязательное
- Единица измерения (Unit) — необязательная
- Статус «готово» (чекбокс)
- Позиция в списке (для не-готовых — ручная сортировка вверх/вниз)
- Фото: до 10 шт., добавление с камеры или из галереи
- Дата создания, дата отметки «готово» — **хранятся в БД «под капотом», в интерфейсе списка не отображаются** (не нужны пользователю на экране)

**Окно ввода / редактирования элемента:**
- Поля (сверху вниз):
  1. **Name** — текст элемента, обязательное. Поле **расширяемое**: начинается с одной строки и растёт по мере ввода до 4 строк, дальше прокручивается внутри себя (длинные названия видно целиком, а не обрезанными в одну строку). Текст при этом остаётся **однострочным по смыслу** — переносы строки в значение не попадают: на клавиатуре вместо Enter стоит Done, вставленные из буфера переносы схлопываются в пробел. При совпадении введённых букв с записями справочника под полем выводится drop-down с вариантами (например, «Мас» → «Масло сливочное», «Масло подсолнечное», «Масло оливковое»); выбор варианта подставляет текст (см. 3.4).
  2. **Quantity** — количество, необязательное.
  3. **Unit** — единица измерения, необязательная.
- Кнопка добавления фото (общий модуль фото, см. раздел 8; лимит 10).
- Up-bar: кнопки **Back** и **Save**.

**Вид строки элемента (слева направо):**
1. Чекбокс «готово»
2. Текст элемента — при статусе «готово» отображается зачёркнутым (strikethrough)
3. Кнопка-иконка «фото» — отображается, только если у элемента уже есть хотя бы одно фото (тап открывает просмотр фото элемента, оттуда же можно добавить ещё, до лимита 10)
4. Кнопка «В словарь» — отображается, только если текста элемента ещё нет в справочнике (сравнение по отформатированному виду, см. 3.4); после нажатия текст сохраняется как запись справочника, кнопка исчезает. Жёсткой связи элемент ↔ справочник нет — справочник лишь база шаблонов для быстрого набора
5. Кнопка «⋯» — контекстное меню элемента: Edit / Delete (см. раздел 8)
6. Ручка «=» (drag handle) — для перетаскивания элемента вверх/вниз внутри списка; отображается только у не-готовых элементов (порядок готовых управляется автоматически)

*Первое фото к элементу (когда кнопки «фото» в строке ещё нет) добавляется через окно ввода/редактирования элемента (кнопка добавления фото, см. выше).*

Поведение:
- Отметка «готово» → элемент визуально переносится под разделитель, становясь **первым** в группе «готово» (сразу под разделителем), остальные готовые элементы сдвигаются вниз. Сортировка внутри групп — только по позиции (`position`), **без привязки к дате/времени отметки**; поле `done_at` хранится как метаданные (для истории/статистики), но не используется для порядка отображения.
- Разделитель — тонкая горизонтальная полоса толщиной 2–4 px, визуально отделяющая активные элементы (сверху) от готовых (снизу).
- Снятие отметки → элемент возвращается наверх, в конец группы «не готово» (либо на прежнюю позицию — **уточнить при разработке UI**, по умолчанию — в конец активной группы).
- Перемещение элемента между списками: пункт меню «Переместить» открывает **один диалог**: сверху перечень элементов списка с чекбоксами выбора (высотой не более 7 строк, дальше — скролл), ниже тумблер «Copy», ниже dropdown со списками назначения (с учётом папок, метка «Папка / Список», корень первым), кнопки OK/Cancel. С галкой «Copy» элементы копируются (вместе с копиями фото), без неё — переносятся. Режима множественного выбора на самом экране списка нет (long-press на элементе не используется).
- Массовая операция над **произвольным** набором элементов одна — перенос/копия нескольких выбранных в другой список через диалог «Переместить» (см. выше). Массовые снятие отметок и удаление — только над всей группой «готово», пунктами меню списка «Удалить отмеченные» и «Снять отметки» (см. 3.2).
- Добавление в справочник — кнопкой «В словарь» на строке элемента (см. выше, п. 4); текст приводится к формату справочника «Xxxxxxxxx» (см. 3.4; «молоко 3.2%» → «Молоко 3.2%», «ХЛЕБ» → «Хлеб»).

### 3.4 Справочник (словарь)
- Отдельный экран справочника: список сохранённых названий (например, «Хлеб», «Молоко», «Мясо» — для покупок), с возможностью добавить / отредактировать / удалить запись. Вверху экрана — поле поиска: с первых введённых букв фильтрует перечень (регистронезависимо, по вхождению).
- Запись справочника может включать **единицу измерения** суффиксом « /ед»: «Молоко /kg». Кнопка «В словарь» на элементе сохраняет название вместе с ед. изм. (если задана); выбор такой подсказки в редакторе элемента заполняет **оба** поля — Name и Unit. Количество в строке элемента отображается в формате **«5/kg»** (только ед. изм. — «/kg», только количество — «5»). Записи отображаются по алфавиту. Форматирование «Xxxxxxxxx» (первая буква заглавная, остальные строчные) применяется ко всем записям справочника, независимо от способа добавления (кнопка «В словарь» на элементе или ручное добавление на этом экране). Дубликаты невозможны: если отформатированный текст совпадает с существующей записью, новая запись не создаётся.
- При добавлении нового элемента в любой список: с **первой** введённой буквы — drop-down с подсказками (автодополнение) из справочника **по вхождению** введённых букв (не только по началу слова; регистронезависимо, включая кириллицу), совпадения по началу слова показываются первыми; выбор подсказки подставляет готовый текст (пример — см. 3.3, поле Name). Поиск на экране справочника — по тем же правилам.
- Справочник общий для всего приложения (не привязан к конкретному списку/папке).
- Вход на экран справочника — из настроек (пункт «Словарь») и/или из экрана добавления элемента.

### 3.5 Режим крупного шрифта
- Включение: долгий тап (long-press) на плавающей кнопке [+] (FAB) на экране списка.
- Выключение: долгий тап (long-press) на той же кнопке [+] (FAB) **или** системная кнопка/жест «назад» — оба способа возвращают на обычный экран списка.
- Пока режим включён:
  - Очень крупный шрифт названий элементов (~40sp), слева у каждой строки — толстая круглая точка-маркер (у готовых — приглушённого цвета)
  - Экран не гаснет, пока открыт этот режим (Android `FLAG_KEEP_SCREEN_ON` / WakeLock) — при условии, что в настройках включён тумблер **Keep screen on (in large font mode)** (см. раздел 5); по умолчанию тумблер включён
  - Тап по элементу — отметка «готово» / снятие отметки (готовые элементы отображаются зачёркнутыми, как и в обычном режиме)
- Редактирование (текст, фото) в этом режиме не предполагается — только просмотр и отметка выполнения.

### 3.6 PIN-защита списка
- Список, защищённый PIN-ом, отображается в общем перечне списков с иконкой «закрытый замок» рядом с названием (визуальный индикатор защиты, видимый до ввода PIN). Комментарий защищённого списка в перечне не отображается (не светить содержимое до PIN-гейта).
- PIN защищает **все операции над списком**: вход (открытие для просмотра/редактирования), удаление, а также пункты меню «Изменить», «В папку» и «Защитить» (отключение защиты или смена PIN) — любая из этих операций требует ввода PIN, если список защищён.
- Пункт меню динамический: «Защитить» у незащищённого списка / «Снять защиту» у защищённого. «Защитить» открывает диалог с маскированным (звёздочки) полем PIN + повтором (без тумблера — вход в диалог уже означает намерение защитить): пустое поле = использовать **PIN по умолчанию** (задаётся в общих настройках; пока он не задан — пустое поле блокируется с подсказкой), заполненное = **свой отдельный PIN** для этого списка. «Снять защиту» — под PIN-гейтом, выключает защиту; смена PIN = снять защиту и защитить заново. Текущий PIN назад в поле не подставляется.
- PIN по умолчанию в настройках: вводится дважды (PIN + повтор), маскируется звёздочками, сохранённое значение нигде не отображается; пустое сохранение очищает PIN.
- При входе в защищённый список — запрос PIN (маскированный ввод); неверный PIN — ошибка и очистка поля.
- Замечание для реализации: т.к. это не шифрование, а только гейт доступа в UI, база данных физически остаётся нешифрованной SQLite-БД. Это осознанное решение пользователя (простота важнее защиты от прямого доступа к файлу БД).

### 3.7 «Поделиться» списком (полностью или частично)
- При выборе «Поделиться» — выбор одного из двух вариантов: **все элементы** или **только невыполненные** (готовые не включаются).
- Формирование текстового представления выбранных элементов (название списка + построчно текст элементов, статус можно отмечать символом, например «✅»/«▢»).
- Передача через стандартный Android Share Intent (Viber, Telegram, SMS, email, «Скопировать в буфер» и т.д.) — без собственного протокола обмена между установками приложения.

### 3.8 Бэкап / восстановление
- **Бэкап:** архив (`.zip`) с содержимым: файл SQLite-базы + папка `photos/` (фото элементов списков и напоминаний) + папка `sounds/` (пользовательские звуки уведомлений) + папка `logs/` (лог-файлы отладки, см. раздел 8) + файл `manifest.json` (версия приложения, версия схемы БД, дата создания). Сохраняется в `Documents/<ИмяПриложения>/backup_YYYYMMDD_HHMMSS.zip`.
- **Восстановление:** выбор архива из Documents (или через системный файловый пикер) → предупреждение о перезаписи текущих данных. Процедура **атомарна**: архив распаковывается и валидируется во временную папку (проверка структуры zip, `PRAGMA integrity_check` БД, версия схемы из `manifest.json`) и только при успехе — замена текущей базы и папок `photos/`/`sounds/`; при любой ошибке текущие данные остаются нетронутыми. Папка `logs/` включается в бэкап, но при restore не восстанавливается (текущие логи устройства не затираются). Если версия схемы в архиве **старее** — при первом открытии прогоняются миграции (см. 6.4); **новее** текущего приложения — restore отклоняется с ошибкой (downgrade невозможен).

### 3.9 Главный экран приложения

Главный экран — общий для приложения. Навигация — **нижний бар (bottom navigation)** (слева направо):
- **Lists** — модуль «Списки» (открыт по умолчанию при запуске).
- **Reminders** — напоминания, которые срабатывают.
- **Notes** — долговременные заметки-карточки (без срабатывания), см. раздел 4A.
- **Settings** — четвёртая кнопка (иконка-шестерёнка **с подписью**, как остальные вкладки); открывает экран настроек (раздел 5) как вкладку (без стрелки «назад»).

Все вкладки живут под единым Top App Bar (см. раздел 8) и общим Scaffold; переключение вкладок сохраняет состояние каждой. Служебные экраны (About, Filters, Tag Filter, Welcome) — **не вкладки**, а отдельные маршруты, вызываемые из меню/жестов (Settings вынесен на бар отдельной кнопкой).

**Вкладка Lists:** перечень папок модуля «Списки» и списков в корне (см. 3.1–3.2).

**Вкладка Reminders:** пять папок-типов *(детали — в разделе 4)* — только «срабатывающие»:
- Папки: **Daily**, **Periods**, **Monthly**, **Yearly**, **Intervals**.
- Разовые (**Once**, без повтора) — **не папка**: их карточки лежат прямо в корне вкладки, под папками (по устройству как вкладка Lists: папки сверху, записи в корне ниже).

**Вкладка Notes:** перечень папок заметок (1 уровень) и заметок в корне — по устройству как Lists, но со своим модулем (раздел 4A). Это записи без срабатывания.

**Top App Bar:**
- Заголовок / название приложения.
- Кнопка **Today** (иконка «часы-будильник», см. 4.11) — **только на вкладке Reminders**.
- **Индикатор фильтров (All / T / F / TF)** — на вкладках **Reminders и Notes** (у каждой своё независимое состояние фильтра): All — фильтры не применены; T — только Tag Filter (4.4); F — только Filters (4.3); TF — оба (складываются, логическое И). Вкладка Lists фильтрами не затрагивается.
- Иконка меню («⋮»).

**Меню («⋮») — набор пунктов зависит от вкладки:**
- Всегда: **Settings** (раздел 5), **About** (4.9).
- На вкладках Reminders и Notes дополнительно: **Clear all filters**, **Filters** (4.3), **Tag Filter** (4.4).
- На вкладке Lists дополнительно: **Словарь** (3.4), **Backup/Restore** (3.8) *(либо в Settings — согласовать при вёрстке)*.

**FAB (плавающая кнопка [+])** — создание в контексте текущей вкладки/папки: на Lists — новый список; на Notes — новая заметка; на Reminders — новое напоминание: в корне вкладки форма открывается с типом One time, в открытой папке-типе — предзаполнена под тип папки (тип можно поменять — запись просто ляжет в другую папку). Вторичная (меньшая) FAB для создания папки — на экранах с перечнем папок Lists и Notes (папки Reminders фиксированные, не создаются).

**Выход из приложения** — системной кнопкой «назад» с корневого экрана (отдельной кнопки Exit в баре нет).

## 4. Reminders (модуль «Напоминалки»)

### 4.1 Общая идея
Есть набор напоминаний вкладки Reminders, разложенных по типам (см. 3.9): разовые **Once** — карточками в корне вкладки, остальные — по папкам-типам **Daily**, **Periods**, **Monthly**, **Yearly**. Заметки (Notes) — **отдельный модуль на своей вкладке**, не относятся к напоминаниям (см. раздел 4A).
Напоминание «взводится» (сохраняется/активируется) при нажатии кнопки **Save** в окне ввода.

**Раскладка напоминаний по типам вкладки Reminders (определяется автоматически по полям формы, а не выбирается вручную):**
- **Once (корень вкладки)** — тип `One time`, без чекбоксов Monthly/Yearly repeat: разовое срабатывание на конкретную дату.
- **Monthly** — тип `One time` + чекбокс `Monthly repeat`. При срабатывании дата автоматически переносится на следующий месяц (с корректной обработкой конца месяца, в т.ч. февраля) и напоминание считается ежемесячным.
- **Yearly** — тип `One time` + чекбокс `Yearly repeat`. Аналогично Monthly, но перенос на следующий год (с обработкой 29 февраля).
- **Daily** — тип `Daily` (одно или несколько времён в день, выбранные дни недели).
- **Periods** — тип `Period` (диапазон From–To, время, дни недели внутри диапазона).
- **Intervals** — тип `Interval` (арифметический повтор: старт + фиксированный интервал `N единиц` — минуты/часы/дни/недели/месяцы).

**Таймер обратного отсчёта (`Timer`) — не тип и не папка.** Это *режим ввода* формы 4.2 (вторая радиокнопка в группе типов): вводится длительность «через N мин/ч», и по Save взводится одноразовая алярма на `now + N`. **В БД не пишется ничего** — ни записи напоминания, ни события, ни признака: таймер целиком живёт в extras своего `PendingIntent` (`TimerAlarm`), поэтому не появляется карточкой в Once, не участвует в фильтрах/Today/бэкапе и **не переживает перезагрузку** (`BootReceiver` перевзводит только то, что есть в БД). Одновременно активен один таймер: новый Save заменяет взведённый (фиксированный id `TimerAlarm.TIMER_ID`). Срабатывание, звук, full-screen alert (4.5) и уведомление — общие с напоминаниями, на транзиентной записи, собранной из extras; Postpone на алерте и «+10 мин» в уведомлении просто перевзводят таймер, а OK/Stop его завершают.

**Календарные типы против арифметического.** Daily/Monthly/Yearly/Period — *календарные* правила (по дням недели, по числу месяца, по окну дат). Interval — *арифметическое*: отсчёт фиксированного промежутка от стартового момента, безотносительно календаря. Они не пересекаются и дополняют друг друга: «каждые 2 недели от 13.07» календарным правилом не выразить, а «по Пн/Ср/Пт» — интервалом. Поэтому Interval добавлен как отдельный тип, а не заменяет существующие.

*Примечание: чекбоксы Monthly repeat и Yearly repeat взаимоисключающие — включение одного автоматически снимает другой (как радио-кнопки); невалидная комбинация невозможна, валидация на Save не требуется (решено, был открытый вопрос №5).*

### 4.2 Окно ввода / редактирования напоминания (поля по порядку сверху вниз)

*Верхняя часть формы (пп. 1–6) — общая для всех типов; состав полей ниже (п. 7) зависит от выбранного типа повторения.*

1. **Title** — текст, краткое название. **Обязательное поле.**
2. **Content** — текст, дополнительное (развёрнутое) описание. Необязательное.
3. **Tags** — теги через запятую.
   - Кнопка **#** — выбор тегов из справочника тегов (справочник тегов пополняется автоматически по мере ввода новых тегов).
   - Кнопка **x** — очистка поля.
   - **Нормализация:** каждый тег обрезается по краям (trim), внутренние повторные пробелы схлопываются, приводится к нижнему регистру; пустые токены отбрасываются. Дубликаты в пределах напоминания и в справочнике исключаются регистронезависимо (`tags.name` хранится нормализованным). Теги, не связанные ни с одним напоминанием **и ни с одной заметкой** (после смены тегов или удаления записи), удаляются из справочника — чтобы облако тегов (4.4) не засорялось (справочник общий с Notes).
4. **Photos (0/10)** + кнопка с иконкой фотокамеры **"+[o]"** — добавление фото, при нажатии запрос источника: камера или галерея. *(Переиспользует общий модуль работы с фото — см. принцип «без дублирования», раздел 8.)*
5. **Date** — поле ввода даты в формате `2026-07-21` + кнопка «календарь» (открывает date-picker) + кнопка **x** (очистить). Валидация формата ввода — тот же переиспользуемый компонент, что и на экране Filters (см. 4.3). Показывается только для типа `One time`; для `Daily` и `Period` скрывается. Расположено **внутри блока полей One time** — под радио-кнопками типа, перед полем Time (см. п. 7 d).
6. **Priority** — виджет **«(–) ★ ★ ★ (+)»**: изменение уровня приоритета кнопками минус/плюс. Диапазон **0–3**: 0 = без приоритета (звёзды в карточке не показываются), 1–3 — закрашенные звёзды (решено, был открытый вопрос №4).
7. **Поля срабатывания** (любая запись здесь — напоминание; записи «без срабатывания» — это модуль Notes, раздел 4A):

   a. **`[v] Active`** — можно отключить срабатывание напоминания, не удаляя его (по умолчанию включено).
   b. **`[ ] Full screen alert`** — при срабатывании вызывается полноэкранный вариант напоминания (а не обычное системное уведомление). Для типа `Period` включён принудительно и не отключается (кнопки Done/Continue периода есть только на полноэкранном алерте, см. 4.5). *Отображается не под Active, а ниже — в общей для всех типов группе полей срабатывания: первым, перед `Loop sound` (см. п. i) и полем `Sound`. Для `Period` — принудительно включён (чекбокс disabled).*
   c. **Группа радио-кнопок**: `(o) One time` / `(_) Timer` / `(_) Daily` / `(_) Period` / `(_) Interval` — выбор типа повторения напоминания.

   c′. **`Timer` (таймер обратного отсчёта)** — режим ввода, а не хранимый тип (см. 4.1). Поля: сегментная рамка `(–) N (+)` с меткой **«Через/After»** и выпадающим списком единиц (только **мин/ч**) — тот же переиспользуемый виджет, что и `Every` у Interval (раздел 8); ряд кнопок быстрых длительностей **+10м / +20м / +30м / +1ч / +2ч** (суффикс слитно, без пробела — так пять кнопок влезают в одну строку; нажатие *заменяет* значение, не прибавляет; надпись — одной центрированной строкой); строка предпросмотра **«Сработает: ГГГГ-ММ-ДД ЧЧ:ММ»**, пересчитываемая раз в секунду. Отсчёт идёт **от момента Save**, а не от ввода; секунды округляются вверх до целой минуты, чтобы таймер не сработал раньше заданного. При выборе режима пустое поле **Title** автозаполняется словом «Таймер». Поля, которые некуда сохранять, скрыты: Tags, Photos, Priority, Active, Date/Time, Monthly/Yearly repeat, Auto-remove; общие поля срабатывания (Full screen alert, Loop sound, Sound) остаются. Save = «старт»: взводит алярму, показывает снэкбар «Таймер запущен до ЧЧ:ММ» и закрывает форму. Валидация: `N ≥ 1`. Каждый вариант — отдельной строкой на всю ширину (метка любой длины при локализации). Набор полей ниже зависит от выбора:

   **Если выбрано `One time`:**
   d. **Time** — поле ввода времени + кнопка «time-picker» (открывает выбор времени) + кнопка **x** (очистить).
   e. Три кнопки быстрого выбора времени в один ряд: **Morning / Day / Evening** — время указано прямо внутри самой кнопки, второй строкой (например, кнопка «Day» содержит внутри себя текст «Day» и ниже «12:30»), значения берутся из настроек (см. раздел 5 → Time presets). Нажатие кнопки подставляет соответствующее время в поле Time.
   f. **`[ ] Monthly repeat`** — чекбокс (превращает разовую дату в ежемесячно повторяющуюся, по числу месяца из поля Date).
   g. **`[ ] Yearly repeat`** — чекбокс (аналогично, повтор ежегодно, по числу и месяцу из поля Date).
   h. **`[ ] Auto-remove after firing`** — чекбокс: автоматически удалять напоминание после срабатывания. **Уточнение по логике:** удаление происходит не мгновенно в момент срабатывания, а на следующий день после **подтверждения** срабатывания (кнопка OK) — поэтому отложенное (Postpone) напоминание не будет удалено раньше, чем сработает.

   *(Поля Monthly repeat, Yearly repeat и Auto-remove after firing показываются только при выбранном `One time`; при `Daily` и `Period` они скрыты.)*

   **Если выбрано `Daily`:** *(базовое поле Date, п. 5 общей формы, скрывается — у Daily нет даты)*
   d′. **Times** — список времён срабатывания (можно добавить несколько): кнопка **+** и «time-picker» для добавления, каждое добавленное время показывается отдельной кнопкой-чипом с крестиком для удаления, например: `(09:13 ✕)`, `(14:52 ✕)`.
   e′. Ряд из двух кнопок: **Every day** / **Weekdays** — пресеты-переключатели своего диапазона: если диапазон кнопки (все дни / Пн–Пт) включён полностью — нажатие выключает его, иначе включает; Weekdays не трогает Сб/Вс.
   f′. Ряд из семи кнопок дней недели: **Mo / Tu / We / Th / Fr / Sa / Su** — переключатели (toggle), какие дни недели входят в повтор; выбранные дни явно подсвечены цветом (primary), невыбранные — приглушённые.

   **Если выбрано `Period`:**
   d″. Базовое поле **Date** (пункт 5 общей формы) **скрывается**.
   e″. **From** — поле даты + кнопка-календарь (date-picker) + кнопка **x** (очистить). Допустимый ввод: полная дата (`2026-07-09`) **или** просто число дня месяца (`9`). **Значение хранится в том виде, как введено** — не превращается в дату (решено, был открытый вопрос №3). Смысл зависит от вида: **числа** = ежемесячно повторяющееся окно (напр. `5`–`11` = дни 5–11 каждого месяца, бесконечно), **даты** = один конкретный одноразовый диапазон (после `To` больше не срабатывает).
   f″. **To** — поле даты + кнопка-календарь (date-picker) + кнопка **x** (очистить). Формат ввода — как у From. From и To должны быть **одного вида**: либо оба числа, либо обе даты (иначе ошибка валидации). Для чисел `From > To` допустимо — окно переходит через границу месяца (напр. `28`–`3` = с 28-го текущего по 3-е следующего месяца, каждый месяц). Дни 29/30/31 в коротких месяцах усечены до последнего дня месяца. Для дат `To` не должен быть раньше `From`.
   g″. **Time** — поле ввода времени + кнопка «time-picker» + кнопка **x**, и три кнопки быстрого выбора **Morning / Day / Evening** (как в `One time`, п. e) — время срабатывания внутри периода.
   h″. Ряд из двух кнопок: **Every day** / **Weekdays**, и далее ряд из семи кнопок дней недели **Mo / Tu / We / Th / Fr / Sa / Su** (как в `Daily`, пп. e′–f′) — какие дни внутри периода From–To задействованы.

   **Если выбрано `Interval`:** *(базовое поле Date, п. 5 общей формы, остаётся видимым — это стартовая дата)*
   d‴. Базовое поле **Date** (пункт 5 общей формы) — **стартовая дата** отсчёта.
   e‴. **Time** — стартовое время + «time-picker» + кнопка **x**, и три кнопки быстрого выбора **Morning / Day / Evening** (как в `One time`, п. e).
   f‴. **Every** — сегментная рамка `(–) | NNNN | (+)` (кнопка минус · поле числа · кнопка плюс, разделённые вертикальными линиями) с меткой «Every/Каждые» на верхней линии рамки, и рядом отдельный выпадающий список единиц `[ единица ▼ ]`. Число `N ≥ 1` **вводится вручную** в поле (напр. 58) или подкручивается кнопками (минус заблокирован на 1). Годы намеренно не включены — для «раз в год» есть тип Yearly. Это и есть интервал повтора. Минимально допустимый интервал — **1 минута** (меньших единиц нет); верхнего предела нет. **Единицы — короткими несклоняемыми суффиксами** (`min / hr / d / wk / mo`, локализуются: рус. `мин / ч / дн / нед / мес`), одинаковыми в выпадающем списке и в подписи карточки (4.6). Фраза условия — наборная: слово-носитель «Every/Каждые» + число + короткий суффикс (напр. «Каждые 3 дн»), поэтому склонения по числу и множества строк-вариантов не требуется.
   *(Чекбоксы Monthly/Yearly repeat, Auto-remove, дни недели и поля Period для `Interval` не показываются: повтор задаётся только парой «старт + интервал».)*

   Далее — общие поля для всех типов повторения:
   i. **`[v] Loop sound`** — чекбокс: зациклить звук до реакции пользователя, длительность цикла = значение **Duration** из настроек (см. раздел 5 → Default sound); по умолчанию включено.
   j. **Sound** — выпадающий список: по умолчанию значение «Default», кнопка **v** открывает список звуков. Кнопка **📎 (file-picker)** — прикрепить свой аудиофайл — видна всегда. Кнопка **▷ (play)** — предпрослушивание — появляется, только если выбран звук, отличный от Default.

**Валидация при Save:**
- `One time`: заданы дата **и время** (оба обязательны; «дата без срабатывания» — это Note, см. 4A).
- `Daily`: минимум одно время в списке Times и хотя бы один день недели (при создании предвыбран пресет Every day).
- `Period`: заданы From и To, задано время, выбран хотя бы один день недели.
- `Interval`: заданы стартовая дата **и** время, `N ≥ 1`, выбрана единица.
- `Timer`: `N ≥ 1` (даты/времени у режима нет — они вычисляются от момента Save).
- При нарушении — сообщение об ошибке (единый компонент снэкбаров, см. раздел 8), Save блокируется.

**Up-bar экрана ввода:**
- Заголовок: **New memo**
- Кнопка **Save** (иконка «дискета»)
- Кнопка **Back**

### 4.3 Экран Filters

Поля (сверху вниз), элементы ввода — те же переиспользуемые компоненты, что и на экране ввода напоминания (пикеры, кнопки очистки и т.д.):
- **Date from** — поле даты + кнопка-календарь (date-picker) + кнопка **x** (очистить).
- **Date to** — поле даты + кнопка-календарь (date-picker) + кнопка **x** (очистить).
- **Tags** — поле тегов (как на экране ввода: через запятую, кнопка **#** выбор из справочника тегов, кнопка **x** очистка).
- **Priority** — тот же виджет, что и на экране ввода `(–) ★ ★ ★ (+)`.

**Применение фильтра дат:** отсекаются только записи с датой (Once/Monthly/Yearly — по `date`; Period — по пересечению диапазона From–To с диапазоном фильтра; Notes — см. 4A.5). Daily не имеет даты и фильтром дат не отсекается.

**Валидация:** оба поля даты проверяются на корректность формата (`YYYY-MM-DD`); дополнительно проверяется, что **Date from** не позже **Date to** (если заполнены оба поля) — при нарушении показывается ошибка, кнопка **v (OK)** блокируется до исправления.

**Up-bar экрана Filters:**
- Кнопка **Back**
- Кнопка **x** (Clear — сброс всех полей фильтра)
- Кнопка **v** (OK — применить фильтр)
- Заголовок: **Filters**

### 4.4 Экран Tag Filter

**Up-bar:** те же кнопки, что и на экране Filters (см. 4.3) — Back, **x** (Clear), **v** (OK); заголовок: **Tag Filter**.

**Тело экрана:** все теги показаны в виде кнопок («облако тегов»), отсортированы по количеству использований — более частые теги идут раньше (в начале) и отображаются более крупным шрифтом. Градация размера шрифта — 4–5 уровней в зависимости от частоты использования тега. После названия тега в скобках указывается количество записей с этим тегом, например: «авто (11)». Справочник тегов общий для Reminders и Notes, но сортировка и счётчик «(N)» — в контексте активной вкладки (на Notes считаются заметки, на Reminders — напоминания).

**Логика фильтра:** фильтр по тегам с этого экрана — самостоятельный (может применяться один), и при этом может складываться (комбинироваться) с общим фильтром с экрана Filters (см. 4.3) — т.е. оба фильтра действуют одновременно (логическое И).

# Done ### 4.5 Экран Full screen alert (полноэкранное напоминание)

Вызывается для напоминаний с включённым `[v] Full screen alert` (см. 4.2, поле b) в момент срабатывания — вместо обычного системного уведомления.

**Состояние 1 — заблокировано (при появлении экрана):**
- Название приложения (**ReminderLists**) — сверху.
- Текущее время — крупно, под названием.
- Блок с текстом напоминания: подпись «Reminder:», ниже — **Title** напоминания (жирным), ниже — **Content** (дополнительное описание, если заполнено; в примере на скриншоте — «воскр 10:30», но это именно текст поля Content, а не автоматически подставляемые день/время).
- Поверх этого блока — полупрозрачный тёмный круг-оверлей с иконкой **замка** и стрелкой **вниз**: элемент разблокировки экрана (свайп или тап-и-протянуть вниз), защита от случайного закрытия напоминания. Пока не разблокировано — текст напоминания притемнён/частично перекрыт этим кругом.

**Состояние 2 — разблокировано:**
- Круг-оверлей с замком исчезает, текст напоминания отображается чётко, фон экрана светлее.
- Появляется блок **«Postpone for:»** с кнопками: **10 MIN / 20 MIN / 30 MIN / 1 HOUR / 3 HOURS / 1 DAY** — отложить срабатывание на выбранный интервал.
- Кнопка **OK** — подтвердить/закрыть напоминание (полностью завершить срабатывание, без отсрочки).

**Вариант для типа `Daily`:** блок «Postpone for:» без кнопки **1 DAY** (только 10 MIN / 20 MIN / 30 MIN / 1 HOUR / 3 HOURS) — логично, т.к. напоминание и так повторится на следующий день.

**Вариант для Monthly / Yearly:** как базовый (Postpone + OK), но кнопка **1 DAY** скрыта — дата срабатывания к этому моменту уже перенесена на следующий месяц/год (см. 4.1).

**Вариант для типа `Period`** (см. 4.2): вместо блока «Postpone for:» + OK — два других варианта:
- **Done** — «готово», напоминание больше не будет срабатывать, период считается закрытым.
- **Continue** — повторить ещё раз в рамках периода (например, завтра, согласно настройкам повтора этого напоминания).

**Обычное системное уведомление** (когда `Full screen alert` выключен) — с кнопками-действиями:
- **+10 min** — отложить срабатывание на 10 минут.
- **Stop** — только остановить звук; само уведомление не закрывается, остаётся в шторке.

# Done ### 4.10 Планировщик срабатываний (архитектура напоминаний)

Модуль напоминаний построен на чистом AOSP `AlarmManager` (без FCM/WorkManager для точных срабатываний — WorkManager не даёт exact-времени).

**Источник правды — поле `reminders.next_fire_at`** (см. схему 6.2): unixtime ближайшего срабатывания или `NULL`, если срабатывать нечему (`active=0`, либо разовый One time уже сработал и дата в прошлом). Глобальный тумблер `enable_reminders` кэш **не обнуляет** — он только отменяет взведённые алярмы и не взводит новые (сортировка и Today продолжают работать). Пересчитывается при Save, после каждого срабатывания, при Postpone, при перевзводе (boot / смена времени). Вычисление по типам:
- **Once** — `date` + `time`.
- **Monthly / Yearly** — ближайшая будущая дата по числу месяца / по числу и месяцу.
- **Daily** — ближайшее из `reminder_times` × активных дней (`weekdays_mask`).
- **Period** — ближайший подходящий день внутри `period_from`–`period_to` × `weekdays_mask`, с `time`.
- **Interval** — наименьшее `старт + k·интервал` (k ≥ 0, `старт` = `date`+`time`), которое строго больше `now`. Если `старт` в будущем — первое срабатывание = сам `старт`. Единица интервала задаёт тип арифметики (см. блок про DST ниже).

`next_fire_at` также используется для сортировки папок (см. 4.6) и отбора в диалог Today.

**Планирование:** одна exact-аларма на напоминание, `PendingIntent` с ключом = `reminders.id` (для точечного обновления/отмены при редактировании). Взводится только ближайшее время; следующее вхождение (Daily/Period/Monthly/Yearly) перевзводится уже после срабатывания. Механизм — `AlarmManager.setAlarmClock()`: exempt от Doze; требование точных будильников покрывается авто-грантуемым `USE_EXACT_ALARM` (см. разрешения ниже). Компромисс — система показывает иконку будильника в статус-баре и выставляет системное «next alarm». **Разнос одновременных срабатываний:** напоминание должно срабатывать как можно ближе к заданному времени, поэтому смещение вводится только при коллизии. Напоминания одной минуты нумеруются по возрастанию id: первый (rank 0) срабатывает ровно на :00, каждый следующий сдвигается на `rank × 3 сек` (20 слотов в минуту). Одиночное напоминание всегда срабатывает на :00. `next_fire_at` хранит чистое время без смещения (сортировка/Today), смещение добавляется только при взводе алярмы; при изменении состава минутной группы (добавили/убрали/сдвинули) она перевзводится целиком, чтобы слоты оставались плотными от :00.

**Приёмники (`BroadcastReceiver`, тяжёлая работа под `goAsync()` + wakelock):**
- `AlarmReceiver` — на срабатывание: показать уведомление / full-screen alert (4.5), запустить проигрывание звука (см. ниже), записать в `reminder_events`, пересчитать `next_fire_at`, взвести следующую алярму.
- `BootReceiver` — на `BOOT_COMPLETED` **и** `MY_PACKAGE_REPLACED` (после обновления приложения): перевзвести аларму для всех активных напоминаний (аларма не переживает перезагрузку — перевзвод обязателен). На `TIME_SET` / `TIMEZONE_CHANGED` — пересчёт `next_fire_at` и перевзвод (детали TZ/DST — открытый вопрос, см. раздел 10).

**Проигрывание звука (`Loop sound`, см. 4.2 п. i):** короткоживущий **foreground-сервис** (`SoundService`), запускаемый из `AlarmReceiver`, проигрывает звук зациклённо до реакции пользователя (OK / Stop / Postpone / разблокировка full-screen) или до истечения `Duration` из настроек, затем `stopSelf()`. Работает одинаково и для full-screen alert, и для обычного системного уведомления. Служебное уведомление сервиса объявлено отложенным (`FOREGROUND_SERVICE_DEFERRED`, без кнопок): система показывает его, только если звук живёт дольше ~10 с, поэтому при типовой длительности оно не появляется вовсе.

**Пропущенные срабатывания** (телефон был выключен, приложение убито `force-stop`, или `enable_reminders` включили обратно — на `BootReceiver`/перевзводе обнаруживается `next_fire_at < now`):
- **Грейс-окно ~10 мин (константа):** если опоздание меньше — это обычное срабатывание на время (в т.ч. full-screen, если задан). Покрывает слак Doze и задержку загрузки.
- **Once / Monthly / Yearly** — catch-up: показать один раз сразу, пометив как пропущенное; при показе Monthly/Yearly переносят дату на следующий период (как при обычном срабатывании, см. 4.1), Once завершается после OK (с учётом Auto-remove).
- **Daily / Period / Interval** — показать одно уведомление за самый недавний пропущенный слот (остальные пропущенные слоты схлопываются), затем взвести ближайший будущий слот. Замену каждого пропущенного слота не делаем. Для `Interval` это особенно важно: частый интервал (напр. каждую минуту) за время сна/выключения устройства накапливает сотни пропусков — все они схлопываются в одно уведомление.
- **Презентация пропущенного:** всегда обычное уведомление, **не full-screen** (полноэкранный алерт для устаревшего события на загрузке перехватывает экран). Если пропущено несколько напоминаний — группировать в сводку «N пропущенных», а не стек алертов.

**Часовые пояса и DST (семантика wall-clock):** время напоминаний — «по стенным часам устройства», а не абсолютный момент. Источник правды — локальные `date`/`time`/`period_from`/`period_to` (без TZ); `next_fire_at` — производный кэш, вычисляемый конвертацией стенного времени в момент через **текущую** зону устройства (`java.time` / `ZonedDateTime`). Отдельная зона на напоминание не хранится (иначе время «тянулось» бы за пользователем при переезде). При `TIMEZONE_CHANGED` / `TIME_SET` — пересчёт `next_fire_at` и перевзвод (напр. «09:30 ежедневно» после смены пояса срабатывает в 09:30 нового пояса). DST: весной несуществующее локальное время сдвигается вперёд (02:30 → 03:00), осенью неоднозначный час берётся по раннему смещению и срабатывает один раз — дефолтов `java.time` достаточно.

**Interval — единица определяет арифметику.** У интервального типа два разных режима отсчёта:
- **minutes / hours** — абсолютный интервал по `Instant` (реальные секунды). DST и смена пояса на него не влияют: «каждые 90 минут» — это ровно 90 минут физического времени, шаг не привязан к стенным часам.
- **days / weeks / months** — по стенным часам (`LocalDate`/`LocalDateTime` в текущей зоне), как остальные типы. `months` усекает короткие месяцы (старт 31-го → последний день месяца), сохраняя якорный день для последующих шагов. При `TIMEZONE_CHANGED`/`TIME_SET` — пересчёт и перевзвод.

**Звук, уведомления и DND:** воспроизведение делает `SoundService` (собственный `MediaPlayer`), поэтому громкость и реакция на режимы устройства управляются приложением явно:
- Напоминание **всегда срабатывает визуально** (full-screen alert или обычное уведомление — по чекбоксу Full screen alert), независимо от режима звука.
- **Звук:** при беззвучном режиме или активном «Не беспокоить» (проверка `AudioManager.getRingerMode()` и `NotificationManager.getCurrentInterruptionFilter()`) звук **не проигрывается**; иначе играет. Система глушит только звук — само напоминание работает.
- **Вибрация:** сопровождает срабатывание **всегда**, независимо от режима — в т.ч. в беззвучном и DND (гасится только звук, вибрация остаётся).
- **Громкость:** `Sound level` (0–100 из настроек) → громкость `MediaPlayer` (0.0–1.0), независимо от системной. `Duration` (0–90 сек) — предел зацикливания `Loop sound` (см. 4.2 п. i).
- **Каналы уведомлений (API 33+):** канал «Reminders» — `IMPORTANCE_HIGH` (heads-up + full-screen intent); отдельный тихий канал `IMPORTANCE_LOW` — для служебного уведомления `SoundService` и для сводки пропущенных (см. выше).
- **Частые интервалы и шторка:** уведомление идёт под стабильным id = `reminders.id` (одно на напоминание), поэтому каждое новое срабатывание **замещает** предыдущее — 60 копий «каждую минуту» в шторке не накапливаются. Для интервала в **минутах** уведомление дополнительно снабжается `setTimeoutAfter(20 сек)` — устаревшее срабатывание само уходит из шторки через 20 секунд. Для прочих единиц таймаут не ставится.
- **Кнопки уведомления интервала:** у типа Interval добавляется действие **Stop repeating** («Прервать») — снимает `Active`, интервал перестаёт срабатывать (пересчёт `next_fire_at` в null, отмена алярмы), звук и уведомление гасятся. Кнопка **+10 мин** у минутного интервала не показывается (бессмысленна — повтор наступит раньше); кнопка **Stop** (гасит только звук, следующее срабатывание остаётся) работает как у всех типов.

**Требуемые разрешения (манифест / runtime):**
- `POST_NOTIFICATIONS` — runtime-запрос на onboarding; без него напоминания (в т.ч. full-screen) не показываются — нужен экран-объяснение.
- `USE_EXACT_ALARM` — авто-грант, т.к. основная функция приложения = напоминания (в отличие от `SCHEDULE_EXACT_ALARM`, который на Android 14+ требует ручного включения пользователем).
- `USE_FULL_SCREEN_INTENT` — для экрана 4.5 (авто-грант для категории будильников/напоминаний). Разворачивает алерт сам только на заблокированном/выключенном экране; при активном использовании телефона система показывает heads-up.
- `SYSTEM_ALERT_WINDOW` («Поверх других приложений») — снимает запрет на запуск activity из фона: с ним full-screen alert (4.5) раскрывается сразу и при разблокированном телефоне. Запрашивается один раз диалогом при первом запуске (после диалога уведомлений); ответ запоминается навсегда (`overlay_prompt_shown`).
- `RECEIVE_BOOT_COMPLETED`, `VIBRATE`, `WAKE_LOCK`, `FOREGROUND_SERVICE` (+ соответствующий `FOREGROUND_SERVICE_*` type для звука).

# Done ### 4.11 Диалог Today

Вызывается кнопкой **Today** (иконка «часы-будильник») на главном экране (см. 3.9). Информационный обзор напоминаний на текущий локальный день.

**Отбор:** вычисляются времена срабатывания, попадающие в сегодняшний день — считаем по расписанию, а не только по `next_fire_at` (он мог уже уйти на завтра после утреннего срабатывания):
Отбираются **независимо от `active`** — Today это обзор дня; выключенные/сработавшие показываются, но помечаются зачёркиванием (см. ниже):
- **Once / Monthly / Yearly** — если разрешённая дата = сегодня → одна запись.
- **Daily** — каждое время из `reminder_times`, если сегодняшний день недели входит в `weekdays_mask`.
- **Period** — если сегодня внутри `period_from`–`period_to` и день недели в маске → запись на `time`.
- **Interval** — попадают интервалы в единицах **hours и крупнее** (каждое сегодняшнее срабатывание — отдельной строкой, как у Daily; максимум ~24 при часовом шаге — не заливает диалог). Интервалы в **минутах исключаются** полностью: сотни слотов за день сделали бы диалог нечитаемым.

Заметки (Notes) в диалог Today не попадают — они не срабатывают.

**Сортировка:** по времени по возрастанию. Между прошедшими и предстоящими временами (по текущему времени) рисуется разделитель — тонкая горизонтальная полоса 2–4 px (как разделитель «готово» в списках, см. 3.3). **Зачёркивание** (вместо приглушения): у активного напоминания зачёркивается только уже прошедшее сегодня время; неактивное (сработавшее разовое или выключенное Daily/Period) зачёркивается целиком (время + Title).

**Строка:** время (крупно) + **Title** + **Priority** (звёзды) + теги (если заданы), иконка типа-папки. Тап по строке открывает форму редактирования (см. 4.2).

**Пустое состояние:** сообщение «Нет напоминаний на сегодня».

**При выключенном `enable_reminders` (режим молчания, см. раздел 5):** записи всё равно показываются (диалог информационный), но сверху — пометка, что срабатывания сейчас отключены.

## 4A. Модуль «Notes» (заметки)

Долговременные заметки-карточки на отдельной вкладке (см. 3.9). **Не срабатывают** (никаких будильников/уведомлений). Устроен как «Списки» (папки + карточки), но с полями напоминания. Схема БД — 6.1a. Компоненты формы и карточки переиспользуются с напоминаниями (раздел 8, «без дублирования»).

### 4A.1 Папки заметок
Один уровень вложенности (папка → заметки; вложенных папок нет), заметка может лежать в корне. Порядок папок — по алфавиту. Поведение и меню действий полностью как у папок списков (см. 3.1), включая правила удаления и PIN (3.6) — «списки» заменяются на «заметки». Как и у папок списков (3.2): после названия папки через пробел — счётчик **«(количество заметок)»**, непустые папки — **жирным**; пустые — без счётчика, обычным начертанием.

### 4A.2 Поля заметки (форма ввода/редактирования)
Сверху вниз (переиспользует компоненты формы напоминания 4.2):
1. **Title** — краткое название, **обязательное**.
2. **Content** — развёрнутое описание, необязательное.
3. **Date** — произвольный текст-дата, **не валидируется** (пример: «33 февраля 2044»); можно оставить пустым. Если текст парсится как `YYYY-MM-DD` — заметка участвует в сортировке и фильтре по дате (см. 4A.5).
4. **Photos (0/10)** — общий модуль фото (камера/галерея, лимит 10, см. раздел 8).
5. **Tags** — теги через запятую, общий справочник и нормализация (см. 4.2 п. 3).
6. **Priority** — виджет «(–) ★ ★ ★ (+)» (тот же, что у напоминаний).

Полей срабатывания (п. 7 формы 4.2 — Active, Full screen alert, тип повтора, времена, звук) у заметки нет. Up-bar формы: заголовок **New note**, кнопки **Save** и **Back**.

### 4A.3 Карточка и действия
Карточка — компоновка как у напоминания (4.6) без строки времени/дней недели и без чекбокса Active: первая строка **Title + Priority**, ниже **Content** (многострочно), ниже **Date** (как текст) и **теги**; иконка «фото», если есть фото; иконка «замок», если заметка PIN-защищена.
- **Кнопка «⋯» в карточке** — меню **Edit / Delete** (long-press не используется, см. раздел 8).
- **Свайп влево** — удаление (с подтверждением), **свайп вправо** — редактирование.
- **Переместить в папку** — как у списков (пункт «В папку»).
- **Поделиться** — Title + Content через общий Share Intent (раздел 3.7).

### 4A.4 PIN-защита
Полностью как у списков (см. 3.6): переключатель «Защитить PIN-ом» (Default PIN из настроек или свой), иконка «закрытый замок» у защищённой заметки, PIN требуется на любую операцию с ней (открыть, изменить, в папку, снять защиту/сменить PIN, удалить).

### 4A.5 Фильтры и сортировка
- **Filters** (4.3) и **Tag Filter** (4.4) применяются к заметкам — со своим независимым состоянием на вкладке Notes; индикатор (All/T/F/TF) в Top App Bar (см. 3.9). Набор полей Filters для заметок: **Date from/to, Tags, Priority**.
- **Сортировка** внутри папки/корня — *по дате, старые сверху (открытый вопрос 6)*: участвуют заметки, чей Date парсится как `YYYY-MM-DD`; остальные (пустая/нераспарсенная дата) — в конец, по алфавиту (Title).
- **Фильтр Date from/to** применяется только к распарсенным датам; заметки с нераспарсенным Date фильтром дат не отсекаются.

## 6. Модель данных (SQLite, черновик схемы)

> Схема покрывает все три модуля: «Списки» (6.1), «Notes» (6.1a) и «Напоминалки» (6.2). Черновая, будет уточняться по мере доработки экранов (особенно логика повторов и истории срабатываний).

### 6.1 Модуль «Списки»

```sql
CREATE TABLE folders (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,
    comment TEXT,
    created_at INTEGER NOT NULL
);

CREATE TABLE lists (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    folder_id INTEGER REFERENCES folders(id) ON DELETE SET NULL,
    name TEXT NOT NULL,
    comment TEXT,
    pin_enabled INTEGER NOT NULL DEFAULT 0,
    pin_code TEXT,              -- NULL = использовать Default PIN
    delete_locked INTEGER NOT NULL DEFAULT 0,  -- защита от удаления (см. 3.2a)
    created_at INTEGER NOT NULL,
    updated_at INTEGER NOT NULL
);

CREATE TABLE items (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    list_id INTEGER NOT NULL REFERENCES lists(id) ON DELETE CASCADE,
    text TEXT NOT NULL,
    quantity TEXT,             -- количество (необязательное, свободный ввод)
    unit TEXT,                 -- единица измерения (необязательная)
    is_done INTEGER NOT NULL DEFAULT 0,
    position INTEGER NOT NULL,
    created_at INTEGER NOT NULL,
    done_at INTEGER
);

CREATE TABLE item_photos (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    item_id INTEGER NOT NULL REFERENCES items(id) ON DELETE CASCADE,
    file_path TEXT NOT NULL,
    position INTEGER NOT NULL
);

CREATE TABLE dictionary (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    text TEXT NOT NULL UNIQUE,
    created_at INTEGER NOT NULL
);
```

### 6.1a Модуль «Notes» (заметки)

> Отдельный модуль (раздел 4A), устроен как «Списки»: папки одного уровня + карточки. Теги — общий справочник `tags` (см. 6.2), фото — общий модуль фото (раздел 8).

```sql
CREATE TABLE note_folders (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,
    comment TEXT,
    created_at INTEGER NOT NULL
);

CREATE TABLE notes (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    folder_id INTEGER REFERENCES note_folders(id) ON DELETE SET NULL,
    title TEXT NOT NULL,                 -- обязательное
    content TEXT,                        -- необязательное описание
    date TEXT,                           -- произвольный текст-дата, не валидируется (см. 4A)
    priority INTEGER NOT NULL DEFAULT 0, -- уровень приоритета (как у напоминаний)
    pin_enabled INTEGER NOT NULL DEFAULT 0,
    pin_code TEXT,                       -- NULL = использовать Default PIN (см. 3.6)
    created_at INTEGER NOT NULL,
    updated_at INTEGER NOT NULL
);

CREATE TABLE note_photos (
    id INTEGER PRIMARY KEY AUTOINCREMENT,

CREATE TABLE note_tags (

    tag_id INTEGER NOT NULL REFERENCES tags(id) ON DELETE CASCADE,

);
```

### 6.2 Модуль «Напоминалки»

```sql
-- Основная таблица напоминаний (все записи — напоминания; заметки — в notes, 6.1a).
-- Папка (Once/Daily/Periods/Monthly/Yearly) не хранится отдельным полем,
-- а вычисляется из набора признаков (см. 4.1); при желании можно кэшировать
-- в поле folder_type для ускорения выборок.
CREATE TABLE reminders (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    title TEXT NOT NULL,                 -- обязательное
    content TEXT,                        -- необязательное описание
    priority INTEGER NOT NULL DEFAULT 0, -- уровень приоритета (диапазон уточняется)

    active INTEGER NOT NULL DEFAULT 1,   -- чекбокс Active (вкл/выкл срабатывание)
    full_screen_alert INTEGER NOT NULL DEFAULT 0,

    -- тип повторения: 0=One time, 1=Daily, 2=Period, 3=Interval
    repeat_type INTEGER NOT NULL DEFAULT 0,

    -- поля для One time (и производных Monthly/Yearly)
    date TEXT,                 -- дата срабатывания 'YYYY-MM-DD'
    time TEXT,                 -- время срабатывания 'HH:MM' (для One time / Period)
    monthly_repeat INTEGER NOT NULL DEFAULT 0,  -- папка Monthly
    yearly_repeat INTEGER NOT NULL DEFAULT 0,   -- папка Yearly
    auto_remove INTEGER NOT NULL DEFAULT 0,     -- Auto-remove after firing

    -- поля для Period
    period_from TEXT,          -- 'YYYY-MM-DD'
    period_to TEXT,            -- 'YYYY-MM-DD'

    -- поля для Interval (старт = date + time выше)
    interval_count INTEGER,    -- N >= 1 (число единиц), NULL для прочих типов
    interval_unit INTEGER,     -- единица: 0=minutes,1=hours,2=days,3=weeks,4=months

    -- дни недели (для Daily и Period): битовая маска, бит0=Mon ... бит6=Sun
    -- NULL/0 => не применяется (для One time)
    weekdays_mask INTEGER,

    -- звук
    loop_sound INTEGER NOT NULL DEFAULT 1,      -- зациклить на Duration из настроек
    sound_uri TEXT,            -- NULL = Default из настроек; системный Uri (content://…) = звук устройства; иначе имя файла в sounds/ (пользовательский)

    -- денормализованный кэш «следующего срабатывания» (unixtime, локальное время).
    -- Единый источник для планировщика (4.10), сортировки папок (4.6) и диалога Today.
    -- NULL => срабатывать нечему (active=0, либо One time уже сработал / дата в прошлом).
    -- Тумблер enable_reminders кэш НЕ обнуляет (только алярмы, см. 4.10).
    -- Пересчитывается при Save, после каждого срабатывания, при postpone, при перевзводе (boot/time-change).
    next_fire_at INTEGER,

    created_at INTEGER NOT NULL,
    updated_at INTEGER NOT NULL
);

-- Времена срабатывания для типа Daily (их может быть несколько за день).
-- Для One time / Period используется reminders.time; для Daily — эта таблица.
CREATE TABLE reminder_times (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    reminder_id INTEGER NOT NULL REFERENCES reminders(id) ON DELETE CASCADE,
    time TEXT NOT NULL         -- 'HH:MM'
);

-- Фото напоминаний (единый по смыслу с item_photos, но отдельной связью).
CREATE TABLE reminder_photos (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    reminder_id INTEGER NOT NULL REFERENCES reminders(id) ON DELETE CASCADE,
    file_path TEXT NOT NULL,
    position INTEGER NOT NULL
);

-- Справочник тегов (пополняется автоматически).
CREATE TABLE tags (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL UNIQUE
);

-- Связь напоминаний и тегов (многие-ко-многим).
CREATE TABLE reminder_tags (
    reminder_id INTEGER NOT NULL REFERENCES reminders(id) ON DELETE CASCADE,
    tag_id INTEGER NOT NULL REFERENCES tags(id) ON DELETE CASCADE,
    PRIMARY KEY (reminder_id, tag_id)
);

-- История/состояние срабатываний (для отсрочек Postpone, отметок Done/Continue,
-- переноса дат Monthly/Yearly, отложенного Auto-remove «на следующий день»).
CREATE TABLE reminder_events (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    reminder_id INTEGER NOT NULL REFERENCES reminders(id) ON DELETE CASCADE,
    fired_at INTEGER,          -- когда сработало (unixtime)
    action TEXT,               -- 'postpone' | 'ok' | 'done' | 'continue'
    postpone_until INTEGER,    -- если отложено — до какого времени (unixtime)
    created_at INTEGER NOT NULL
);
```

### 6.4 ORM, версионирование, миграции, индексы

**ORM:** Room (Jetpack) поверх этой схемы — Entity/DAO, типобезопасные запросы, встроенное управление `PRAGMA user_version`. Включён schema-export в JSON (для диффа схемы между версиями и как основа тестов миграций).

**Версионирование и миграции:** версия БД растёт на 1 за каждое изменение схемы; для каждого перехода — явный Room `Migration(from, to)`. В release-сборке `fallbackToDestructiveMigration` **не используется** (потеря данных недопустима) — только полноценные миграции; отсутствующая миграция считается ошибкой (падает тест миграций, см. раздел о тестировании). Миграции применяются и при обычном обновлении приложения, и при восстановлении старого бэкапа (см. 3.8).

**Индексы:**
```sql
CREATE INDEX idx_lists_folder            ON lists(folder_id);
CREATE INDEX idx_items_list              ON items(list_id, is_done, position);
CREATE INDEX idx_item_photos_item        ON item_photos(item_id);
CREATE INDEX idx_reminder_photos_remind  ON reminder_photos(reminder_id);
CREATE INDEX idx_reminder_times_remind   ON reminder_times(reminder_id);
CREATE INDEX idx_reminder_tags_tag       ON reminder_tags(tag_id);
CREATE INDEX idx_reminders_next_fire     ON reminders(next_fire_at);

CREATE INDEX idx_notes_folder            ON notes(folder_id);
CREATE INDEX idx_note_photos_note        ON note_photos(note_id);
CREATE INDEX idx_note_tags_tag           ON note_tags(tag_id);
```
*(Первичный ключ `reminder_tags(reminder_id, tag_id)` / `note_tags(note_id, tag_id)` уже покрывает выборку тегов по записи; отдельный индекс по `tag_id` — для обратной выборки «записи по тегу» в Tag Filter.)*

## 7. Нефункциональные требования
- Offline-first, без обязательного интернета для базовой работы.
- Минимальная поддерживаемая версия Android — см. раздел 9.
- Локализация строк через стандартный механизм Android (strings.xml по языкам).
- Фото хранятся в `internal storage` приложения (`photos/`), в БД — только имя файла. Звуки уведомлений — **системные** (alarm-рингтоны устройства, в БД — их системный Uri) либо **пользовательские** файлы, добавленные через file-picker и скопированные в `sounds/` (в БД — имя файла).
- **Иконка и splash:** адаптивная иконка приложения (foreground/background) + монохромная иконка для уведомлений; экран-заставка через AndroidX Core SplashScreen API (`androidx.core.splashscreen`).
- **Доступность (accessibility):** у всех иконочных кнопок — `contentDescription` (для TalkBack); минимальный тач-таргет 48 dp; уважение системного масштаба шрифта (кроме намеренного режима крупного шрифта, см. 3.5); контраст и семантические цвета — через дизайн-токены; тип снэкбара дублируется иконкой (для дальтонизма, см. раздел 8).

## 8. Общие архитектурные принципы (сквозные требования)

Эти требования касаются всего приложения целиком (всех трёх модулей) и обязательны к соблюдению при разработке — чтобы не плодить дублирующийся код и несогласованный UI.

- **Никакого дублирования функциональности.** Если одна и та же возможность нужна в нескольких местах приложения (например, работа с фото нужна в элементах списков, в напоминаниях и в заметках), она реализуется **одним общим переиспользуемым модулем/компонентом**, а не копипастится. В частности:
  - **Фото** — единый модуль: выбор источника (камера/галерея), сохранение в `internal storage`, отображение миниатюр, полноэкранный просмотр (листание, pinch-zoom щипком и double-tap увеличение/сброс; листание страниц работает при масштабе 1x), лимит количества. Используется везде, где в приложении есть фото. Реализация:
    - **Галерея** — системный Android Photo Picker (`PickVisualMedia`), без разрешений на доступ к медиа (Android 13+).
    - **Камера** — `ACTION_IMAGE_CAPTURE` (contract `TakePicture`) с URI через `FileProvider`; снимок делает системное приложение камеры, поэтому разрешение `CAMERA` **не запрашивается**. Итог: модуль фото не требует ни одного runtime-разрешения.
    - **Импорт:** привести к вертикали по EXIF (повернуть и сохранить «уже правильно», сбросив orientation), ресайз до макс. стороны ~2048 px, JPEG ~85% — чтобы файлы были компактными; сохранить в `photos/` под сгенерированным именем, в БД — только имя файла.
    - **Миниатюры/загрузка:** библиотека Coil (open-source, без Google-сервисов) с даунсемплингом и кэшем — отдельные файлы миниатюр не храним.
    - **Удаление файлов:** при удалении фото/элемента/напоминания репозиторий удаляет файлы с диска (Room CASCADE чистит только строки БД). Дополнительно — подметание «сирот» при старте приложения и после restore: файлы в `photos/`/`sounds/` без ссылки в БД удаляются.
    - **Удаление фото из просмотра** — диалог подтверждения с чекбоксом **«Сохранить в галерею»** (по умолчанию выключен): при включении фото перед удалением копируется в системную галерею (`Pictures/<AppName>` через MediaStore, без разрешений).
  - Аналогично — для PIN-диалога, шаринга через Share Intent, работы со справочником и т.п.: одна реализация на всё приложение.
- **Единый компонент поля ввода с плавающей меткой (floating label).** Все текстовые поля приложения — один переиспользуемый компонент: название поля изначально отображается внутри поля (по середине), при фокусе или заполнении «перепрыгивает» вверх, в рамку поля (паттерн Material `OutlinedTextField` с label). Разнотипных полей по экранам быть не должно.
- **Автофокус первого поля.** При открытии любого диалога/формы ввода курсор сразу ставится в первое текстовое поле (фокус + клавиатура), без дополнительного тапа. Правило сквозное для всего приложения.
- **Кнопки диалогов — с цветным фоном.** Все кнопки действий в диалогах (Save, Cancel, Delete, OK и т.п.) — не текстовые, а залитые цветом: подтверждение — filled primary (для деструктивных действий — error-цвет), отмена — filled secondary. Один общий компонент кнопок диалога на всё приложение; цвета — из токенов темы.
- **Название объекта в диалогах подтверждения** (удаление и т.п.) выводится как есть: без кавычек и без знака вопроса — заголовок диалога уже описывает действие.
- **Строка записи — единый шрифт.** Все текстовые части строки записи (текст элемента, количество, единица и т.п.) — одного размера и одного цвета; вторичные части не уменьшаются и не осветляются. У выполненных — зачёркивание применяется ко всем частям строки.
- **Компактные формы ввода**: поля формы собраны по вертикали плотно — единый малый интервал (~4dp) между полями, уменьшенные (36dp) touch-цели рядов чекбоксов/радио, счётчик длины поля показывается только при фокусе (у неактивного поля нет пустой строки под ним).
- **Контекстное меню записи — кнопкой «⋯» в строке/карточке** (Edit / Delete и др. по контексту), меню открывается у кнопки. **Long-press на записях не используется** — long-press зарезервирован за FAB (вход/выход режима крупного шрифта, см. 3.5) и за самим режимом крупного шрифта. Удаление — всегда с диалогом подтверждения.
- **Единый компонент выпадающего меню** на всё приложение, с явным цветным фоном из токенов темы — общий токен фона для всех всплывающих поверхностей: меню «⋮» топ-бара, контекстные меню записей и drop-down автодополнения.
- **Иконки меню:** меню приложения в топ-баре — три вертикальные точки («⋮»); меню на строках записей/папок — три **горизонтальные** точки («⋯»), чтобы визуально различались.
- **Названия пунктов меню не должны пересекаться словами.** Два пункта одного меню не могут начинаться с одного слова или быть уточнением друг друга («Защитить» и «Защитить от удаления» — так нельзя). Каждый пункт называется по своему ключу или действию — «Закрыть PIN-ом» / «Запретить удаление» (см. 3.2a). Правило распространяется на любое меню приложения.
- **Свайпы на записях:** вправо — Edit, влево — Delete (с тем же подтверждением). Сквозной паттерн для строк-записей во всех модулях.
- **Системные инсеты:** на экранах без нижнего бара контент и FAB не должны заходить под системную навигацию (navigation bar padding); формы ввода — с отступом под клавиатуру (IME padding). FAB никогда не выпадает за низ экрана.
- **FAB на одном уровне на всех экранах:** высота нижнего бара измеряется один раз при старте и хранится как общий токен; каждый FAB на любом экране (с баром или без) сразу рисуется на этом уровне от низа окна — кнопка никогда не «прыгает» при переходах. Нижний бар — только на трёх вкладках.
- **Компактный нижний бар:** высота содержимого бара — 64dp (меньше дефолтных 80dp M3) плюс системный инсет жестов. Активная вкладка выделяется явно: индикатор-«пилюля» цветом `primary`, иконка — `onPrimary`, подпись — `primary`. Подписи вкладок — всегда одна строка (при большом масштабе шрифта не переносятся, обрезаются с многоточием).
- **Навигация без дублей:** переходы на экраны защищаются от повторного срабатывания (launchSingleTop и т.п.) — свайп/двойной тап не должны укладывать в стек несколько копий экрана.
- **Общий Top App Bar («up-bar»).** Единый переиспользуемый компонент верхней панели (заголовок экрана, кнопка «назад», иконка меню «⋮» с пунктами действий) — используется на всех экранах приложения с одинаковым поведением и внешним видом, а не верстается заново на каждом экране.
- **Дизайн-токены вместо захардкоженных значений.** Цвета, шрифты — размеры (font size), начертание/жирность (font weight), межстрочные интервалы — задаются централизованно через переменные темы (в терминах Jetpack Compose — `MaterialTheme` / кастомная `ColorScheme` и `Typography`), а не прописываются напрямую в каждом экране. Это касается в том числе тем оформления из настроек (см. 5) — переключение темы должно менять цвета глобально через один источник правды, а не в каждом компоненте отдельно.
- **FAB — в цвете темы.** Все плавающие кнопки (основная и вторичная малая) — один общий компонент на всё приложение, фон — primary-цвет активной темы (контент — onPrimary), из токенов темы, не дефолтные Material-цвета и не локальные значения.
- **Чёрный текст в светлой теме.** В светлой теме весь текст и второстепенные подписи/иконки — чистый чёрный (токены `onSurface`, `onSurfaceVariant`, `onBackground`, `outline` = Black), без бледно-серых надписей. Теги тоже монохромные: строка тегов на карточках — чёрная (не акцентный `primary`) и **италиком** для визуального отличия, выделенный чип в тег-фильтре — инверсия (чёрный фон, светлый текст), а не цветная заливка. Исключения — намеренно приглушённые состояния (пустые звёзды приоритета, disabled) через `outlineVariant`, и текст на цветных заливках (кнопки, FAB, пилюля активной вкладки, снэкбары), где остаётся светлый контентный цвет для контраста. Тёмная тема — **чистый чёрный** фон и поверхности (не тёмно-серый Material), текст белый (`onSurface`/`onBackground` = White), а акцент — яркий тон под каждый пресет (`accentDark`), т.к. «сырой» seed на чёрном не читается. `surfaceVariant` — почти чёрная приподнятая поверхность для чипов; фон меню (`secondaryContainer`) и диалогов (`surfaceContainerHigh`) остаётся серым для отделения от чёрного. Пресетов восемь: Teal, Indigo, Forest, Plum + тёплые Amber/Orange/Beige/Olive. Цвет контента на акценте/primary адаптивный по яркости (`luminance > 0.5` → чёрный, иначе белый), чтобы текст/иконки читались на любом пресете в обеих темах.
- **Единый компонент уведомлений (цветные снэкбары).** Вместо стандартных «бледных» системных снэкбаров — один переиспользуемый компонент с семантической цветовой кодировкой по типу сообщения:
  - **Error** — красный;
  - **Warning** — оранжевый;
  - **Success / OK** — зелёный;
  - **Info** — синий.
  - Дополнительно к цвету — иконка слева, соответствующая типу (чтобы тип считывался не только по цвету — важно для доступности/дальтонизма). Цвета берутся из дизайн-токенов темы (см. выше), чтобы согласовываться с выбранной темой оформления. Длительность показа зависит от типа (ошибки — дольше или до закрытия пользователем; success/info — короче). Используется во всём приложении для всех системных сообщений (ошибки валидации, успешный бэкап, предупреждения и т.п.).
- **Логирование ошибок (для отладки).** Приложение может вести локальный лог-файл на устройстве (напр. `logs/` в internal storage), куда записываются ошибки и ключевые события (исключения, сбои бэкапа/восстановления, ошибки постановки/срабатывания напоминаний). Каждая запись — с меткой времени и уровнем (ERROR/WARN/INFO). Логи:
  - Запись в файл управляется тумблером **«Write logs to file»** в настройках (см. раздел 5), по умолчанию **выключена**. При выключенном тумблере запись в файл не ведётся.
  - Пишутся **только локально**, никуда не отправляются (в русле общей приватности — без облака/телеметрии).
  - Имеют ограничение размера с ротацией (напр. хранить последние N файлов / последние сутки-двое), чтобы не разрастаться.
  - Включаются в бэкап-архив (папка `logs/`), чтобы при разборе проблемы их можно было приложить.
  - В debug-сборке пишутся подробнее (в т.ч. в logcat); в release — только важное, без чувствительных данных пользователя (тексты записей, PIN не логируются).
- **Пустые состояния (empty states).** Каждый экран с перечнем при отсутствии данных показывает единый по стилю placeholder (иконка + короткий текст + подсказка действия): пустая папка/корень «Lists», список без элементов, пустой справочник, папки напоминаний без записей, пустая выдача фильтров, облако тегов без тегов, диалог Today (4.11). Компонент empty-state — общий переиспользуемый.
- **Лимиты ввода.** Максимальная длина текстовых полей задаётся централизованно и показывается счётчиком в общем компоненте поля ввода (floating label): имена папок/списков и Title ≤ 100, текст элемента ≤ 200, Content ≤ 2000, комментарий ≤ 500, тег ≤ 30, Quantity/Unit ≤ 20 символов. Длинные перечни рендерятся через `LazyColumn` (виртуализация) — спец-обработки не требуют.

## 9. Технологический стек и сборка

- **Язык:** Kotlin.
- **UI-тулкит:** Jetpack Compose.
- **Платформа разработки:** Linux.
- **Зависимости:** только чистый AOSP/Jetpack — без Google Play Services, Firebase и прочей проприетарной Google-инфраструктуры (в т.ч. без push-уведомлений через FCM, без облачного бэкапа через Google-сервисы — бэкап только локально в Documents, см. 3.8).
- **Сборка:** через Gradle (Kotlin DSL), вручную из командной строки / shell-скриптами (`./gradlew assembleDebug` / `assembleRelease` и т.п.), без обязательного использования Android Studio и без настройки CI/CD на данном этапе.
- **Минимальная версия Android:** API 33 (Android 13+). *Замечание: это ограничивает аудиторию только относительно новыми устройствами — стоит ещё раз явно подтвердить перед стартом разработки, так как более старая база (API 26) охватила бы заметно больше реальных устройств.*
- **Тестирование:** упор на JVM-unit-тесты критичной логики (без CI, запуск локально `./gradlew test`): вычисление `next_fire_at` для всех типов (Once/Monthly/Yearly/Daily/Period), перенос конца месяца и 29 февраля, DST/смена пояса, разрешение пропущенных срабатываний (4.10), нормализация тегов/справочника, формирование текста «Поделиться». Миграции БД — тесты через Room `MigrationTestHelper` на экспортированных схемах. Бэкап/restore — round-trip тест (архив → восстановление → сверка данных). Инструментальные UI-тесты на данном этапе не обязательны.

## 10. Открытые вопросы / допущения, требующие подтверждения

**Списки:**
1. При снятии отметки «готово» — элемент возвращается в конец группы «не готово» (не на исходную позицию). Подтвердить.
2. Как отображаются Quantity и Unit в строке элемента (например, после текста: «Молоко 2 л») и включать ли их в текст «Поделиться» (см. 3.7).

**Напоминалки:**
3. ~~Точная логика определения месяца/года, когда в полях Period From/To введено только число дня~~ — **решено**: ближайший будущий (From — от сегодня, To — от From), см. п. 4.2 e″/f″.
4. ~~Priority — сколько уровней у виджета `(–) ★ ★ ★ (+)`~~ — **решено**: 0–3, звёзды, см. п. 4.2 п. 6.
5. ~~Взаимодействие Monthly repeat и Yearly repeat при одновременном включении~~ — **решено**: взаимоисключение (как радио), см. 4.1.
6. Сортировка Notes «по дате, старые сверху» — окончательно подтвердить (пользователь пометил «надо обдумать»). Сортировка папки Once — явно не задана (предположительно по дате срабатывания). См. 4.6.

**Отложено на будущие версии (сознательное решение, не в v1):**
- Поиск по спискам / элементам / заметкам / напоминаниям. При возврате к фиче: глобальный поиск с главного экрана, но **исключая содержимое PIN-защищённых списков и заметок** (иначе утечка содержимого мимо гейта).
