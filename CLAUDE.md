## Состояние проекта

Каркас проекта создан по ТЗ: Gradle (Kotlin DSL) + Compose + Room + Coil, single-Activity, три вкладки нижнего бара, полная схема БД (Room entities/DAO), общие UI-компоненты и стабы движка напоминаний. Логика в стабах помечена `TODO` со ссылками на разделы ТЗ. Полное техническое задание — `ReminderLists-TZ.txt` (на русском). Перед любой работой по функциональности читать соответствующий раздел ТЗ; открытые вопросы собраны в разделе 10 ТЗ — по ним уточнять у пользователя, а не принимать решения молча.

Стартовый экран приветствия (ТЗ 4.8) **отменён** — никакого Welcome-диалога/маршрута нет. Первый запуск: язык от системы (fallback — английский), тема — дефолт из настроек (ТЗ 4.8 / 5).

## Сборка / установка

Тулчейн и скрипты — как в сиблинг-проектах (`../myplayer`, `../memlists`): AGP 9.1.1, Gradle 9.3.1, JDK 17/21, compileSdk 36, **minSdk 33** (ТЗ 9). Версии — в `gradle/libs.versions.toml`.

**Отличие от myplayer/memlists:** здесь нужен Room (генерирует код через KSP). AGP 9 использует built-in Kotlin — плагин `org.jetbrains.kotlin.android` запрещён (AGP падает с ошибкой, если его применить). Поэтому применяются только `kotlin-compose` + `ksp` (как у сиблингов, плюс KSP). Версию Kotlin задаёт compose-плагин, и KSP обязан ей соответствовать: **Kotlin 2.3.20 + KSP 2.3.9 + Room 2.8.4** (KSP 2.3.9 собран ровно под Kotlin 2.3.20). Schema-export Room — `app/schemas` (`room.schemaLocation`).

Скрипты (пользователь запускает сам — не собирать/устанавливать автоматически):
- `10-MakeRelease.sh` — бампит `build_number.txt`, `./gradlew assembleRelease`, ABI-сплиты + universal, переименование в `reminderlists-<version>-<build>-<abi>.apk`. Линия `major.minor` поднимается сама, когда в `CHANGELOG.md` под `Unreleased` ждёт запись `N`, а последний тег вышел на текущей линии — фича поднимает её один раз, а не на каждой следующей сборке.
- `11-EmulRELEASE.sh` (x86_64 эмулятор) / `12-SamsRELEASE.sh` (arm64 устройство) — установка. `02-DebugWiFiConn.sh` — adb по Wi-Fi.
- `18-ToUpdate.sh` — публикует arm64-релиз на сервер обновлений вместе с манифестом, который
  читает встроенный updater. Наличие скрипта означает, что updater вписан в приложение.
- `00-MakeAll.sh` — весь прогон одной командой: релиз, обе установки, сервер обновлений, ссылки в `OUT/`.
- `19-LinkOut.sh` — жёсткие ссылки на arm64 и universal APK в `OUT/` под их собственными именами,
  всё остальное из папки выметается.

Конвенции: `build_number.txt` бампит только `10-MakeRelease.sh` — не редактировать вручную, но проверять его статус перед каждым коммитом и `git add`, чтобы версия в репозитории не расходилась со сборкой. Подпись release читает `/home/e/.my-safe/key.properties` (fallback — `key.properties` в корне); keystore и `key.properties` — в `.gitignore`, без них APK не подписан.

## Что за приложение

**ReminderLists** — локальное (offline-first) Android-приложение с единой SQLite-базой и **тремя модулями** (три вкладки нижнего бара, порядок `Lists · Reminders · Notes`, Lists по умолчанию — раздел 3.9 ТЗ):

1. **Списки** (раздел 3 ТЗ) — чек-листы с папками (один уровень вложенности), фото у элементов (до 10), справочником автодополнения («словарь»), PIN-защитой отдельных списков, режимом крупного шрифта, шарингом через Share Intent и бэкапом в zip.
2. **Напоминалки** (раздел 4 ТЗ) — напоминания, автоматически раскладываемые по пяти папкам-типам (Once / Daily / Periods / Monthly / Yearly) **по полям формы, а не вручную**; теги, приоритет, full-screen alert, postpone. Движок — `AlarmManager` (`setAlarmClock`), кэш `next_fire_at`, `SoundService`, обработка пропущенных срабатываний и DST (раздел 4.10 ТЗ).
3. **Notes** (раздел 4A ТЗ) — долговременные заметки-карточки **без срабатывания**; устроены как «Списки» (папки 1 уровня), поля Title/Content/Date/Photo/Tags/Priority, PIN как у списков, свои фильтры (Filters + Tag Filter).

Скрытого режима нет (удалён): защита приватности — только PIN-гейт на списках (3.6) и заметках (4A); напоминания не защищаются. PIN — только UI-гейт, БД не шифруется (осознанное решение).

Схема БД — раздел 6 ТЗ (три группы таблиц: списки 6.1, Notes 6.1a, напоминания 6.2 + `settings` ключ-значение). ORM — Room с версионированием/миграциями и schema-export (6.4).

## Технологический стек (раздел 9 ТЗ)

- Kotlin + Jetpack Compose, Gradle (Kotlin DSL).
- Минимальный API 33 (Android 13+).
- **Только чистый AOSP/Jetpack** — никаких Google Play Services, Firebase, FCM, облачных сервисов. Бэкап только локально в `Documents/<AppName>/`.
- Сборка из командной строки: `./gradlew assembleDebug` / `assembleRelease` (без Android Studio, без CI/CD). Помнить: пользователь собирает и устанавливает сам — не запускать сборку автоматически.

## Архитектурные принципы (раздел 8 ТЗ — обязательны)

- **Никакого дублирования**: фото (камера/галерея, хранение в internal storage, миниатюры, полноэкранный просмотр, лимит), PIN-диалог, шаринг, справочник — по одному переиспользуемому модулю на всё приложение.
- **Единый Top App Bar** — один компонент верхней панели для всех экранов.
- **Дизайн-токены**: цвета/типографика только через `MaterialTheme` (кастомные `ColorScheme` / `Typography`), никаких захардкоженных значений — темы из настроек переключаются через один источник правды.
- **Единый компонент снэкбаров** с семантическими цветами (Error красный, Warning оранжевый, Success зелёный, Info синий) + иконка типа.
- **Локальное логирование** в файл (тумблер в настройках, по умолчанию выключен), с ротацией, без отправки куда-либо; PIN и тексты записей не логировать.
- Фото и звуки — в internal storage (`photos/`, `sounds/`), в БД только путь/имя файла.
- Локализация: strings.xml, базовый английский + украинский и русский. UI-строки не хардкодить.
